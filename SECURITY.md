# Security policy

## Reporting a vulnerability

Do not publish exploit details, credentials or private meeting data in a public issue or pull request.

If this repository's **Security** tab offers **Report a vulnerability**, use it to submit a private report. If that option is unavailable, open an issue titled **Private security reporting contact requested** with no vulnerability details. A maintainer must arrange a private channel before you send the report. No dedicated security email or response-time commitment is currently published.

Once a private channel is available, include the affected version and platform, a description of the impact, and minimal reproduction steps using synthetic data. Do not test against someone else's meetings, accounts or cloud storage.

## Fixes and supported versions

Report which version you tested. Security fixes target the latest source and subsequent releases; older releases do not have a separate maintenance commitment. A published version number does not imply that a security audit has been completed.

## Handling a report

Maintainers should acknowledge the report privately, reproduce it with synthetic data, agree on a fix and disclosure plan with the reporter, and publish affected versions and remediation when the fix is available. Never include secrets or private recordings in the advisory.
